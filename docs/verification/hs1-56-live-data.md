## 实现

- LiveWorkspaceSync 先显示编辑，再异步持久化与提交；未获服务器确认不标记云端成功。
- 原失败队列迁移到保留草稿区，单个无效验收或业务请求不再堵住后续有效修改。401 与不确定网络结果保留原请求；不静默丢弃。
- 即时操作投影只复制受影响记录和 items 数组，避免深拷贝整个工作空间。
- 新 live-v1 API 以服务器最新数据应用精确业务操作，保留权限、业务规则、事务与请求去重。长文本使用编辑基准防止静默覆盖，旧文本草稿缺少基准且已过期时转人工处理。
- 当前项目在原存储结构中维护一份可变 JSON 数据，不再采用 15 分钟历史保存窗口。已有命名/压缩历史不被覆盖或删除；首次迁移最多新增一份当前数据，此后原位更新。
- 内部 head 仍用于缓存失效与兼容旧客户端，不作为新版保存的整文件冲突门槛。内容要求标识仍用于确保 AI 交付对应当前验收要求。
- 访问立即校验服务器最新内容；合并后的 /state 接口在一次网关调用中返回变化项目，未变化时不重绘。
- 长轮询保持更新通知等待，网页和 MCP 保存提交后唤醒对应账号。重连及超时根据数据库补查，不依赖通知不丢失的假设。通知仅含已授权账号项目的元数据。
- 保存请求基准仍为当前服务器数据时返回记录增量；并发导致基准已变化、请求重放时返回完整最新项目，避免漏掉其他人的修改。晚到确认不会覆盖较新的云端数据。
- 编辑中不弹离开提醒、不显示常驻同步浮层；未提交或失败草稿仅在离开浏览器页面时触发守卫，项目设置保留草稿处理入口。
- 云空间仅对已迁移的 HeySO 项目隐藏版本管理入口；BaizeFig 原文件版本和保存接口保持原行为。
