## 快速开始

从建立项目到完成第一次交付，认识 HeySO 的基本用法。

### HeySO 能帮你做什么

合序 HeySO 用于管理人与 AI 共同推进的项目：记录目标，拆解工作，安排时间和冲刺，跟踪状态，检查交付，保存项目共识。本文适用于 alpha_0.1，依据当前功能编写，更新于 2026 年 11 月 6 日。

你可以按顺序完成本篇练习，也可以在左侧选择主题，或搜索“记忆”“启动冲刺”“恢复”等关键词。顶栏可下载整本用户手册；“返回工作台”会关闭帮助。

### 完成你的第一个工作项

1. 进入工作空间，在项目入口新建项目，填写名称、编号、目标和项目周期。已有项目可直接打开。
2. 进入「项目设置 → 常规」检查目标与周期；在「协作约定」填写共同工作方式和完成定义。
3. 在项目页面的新建入口或右键菜单创建故事、任务或缺陷。填写清晰标题、负责人、计划日期和验收标准。
4. 如果目标较大，在详情的子任务或子项页签中拆解。给每个执行项写明可检查的结果。
5. 进入「冲刺」创建冲刺，从待办池安排本轮工作；也可直接在清单和看板推进，不必先创建冲刺。
6. 按工作流更新状态。需要 AI 协作时先配置 MCP，再启用目标工作项的 AI 执行，将执行指令交给已连接的 AI。
7. 检查成果及验证说明，需要人工验收时选择通过或要求修改。完成后可纳入版本发布，并把长期有效的决定写入记忆。

### 如何写一条可执行的需求

| 字段 | 示例 |
| --- | --- |
| 标题 | 支持按负责人筛选旅行路书 |
| 描述 | 用户需要从列表中找到自己负责的路书；筛选后保留当前搜索条件。 |
| 验收标准 | 能选择负责人并显示匹配结果；清空后恢复全部；无匹配结果时展示提示。 |
| 交付证据 | 可访问的预览链接、改动说明和上述场景的验证结果。 |

创建时可暂缺部分内容；启动冲刺前，纳入的标准工作项必须具备负责人和验收标准。是否完成以工作流和实际验收为准。

## 界面与基本概念

找到合适的页面，分清项目、工作项、冲刺和版本。

### 页面入口与用途

| 入口 | 什么时候使用 |
| --- | --- |
| 仪表盘 | 跨项目查看待办、逾期、今日到期、待验收及阻塞工作。 |
| 项目入口 | 创建、打开和切换项目。 |
| 线路 | 查看父子工作项、计划周期和版本里程碑，调整排期。 |
| 冲刺 | 管理待办池，安排本轮范围，启动、完成冲刺并复盘。 |
| 看板 | 按状态推进工作，拖动卡片并调整列内顺序。 |
| 清单 | 查询项目全部工作项，配置列、排序和筛选。 |
| 发布 | 组织版本范围，记录发布结果、交付快照和发布说明。 |
| 报告 | 选择报告、配置范围、生成分析并查看明细。 |
| 智能 | 查看 AI 执行记录、阻塞和待人工验收的交付。 |
| 项目设置 | 维护项目、成员、角色、类型、工作流、协作约定、记忆、连接与备份。 |

### 用仪表盘确定今天的重点

1. 点击顶栏「仪表盘」，查看整个工作空间的待办。
2. 选择全部待办、已逾期、今日到期、待验收或有阻塞，按项目和负责人筛选，也可搜索所有项目待办。
3. 点击待办直接打开对应工作项；项目汇总区可快速进入项目或创建新项目。
4. 需要检查最新状态时点击刷新仪表盘。已完成及已取消工作不计入待办，标准工作项与子任务均会显示。

### 几个容易混淆的概念

| 概念 | 含义 |
| --- | --- |
| 类型 | 工作性质，例如故事、任务、缺陷。 |
| 状态 | 当前处理位置，例如待开始、执行中、待验收。 |
| 父子关系 | 工作拆解关系；父级可暂留空，子任务交付或 AI 执行前需关联标准工作项。 |
| 冲刺 Sprint | 在固定时间内推进的一轮工作，保存启动范围和结束结果。 |
| 版本 Release | 准备一起交付的一组成果；与冲刺分别安排。 |
| 故事点 SP | 相对工作量估算，不等同于小时。0 表示未估算。 |
| 工作项编号 | 项目编号加顺序号，例如 HS1-12；详情中可以复制。 |
| 历史快照 | 冲刺结束或版本发布时保留的内容，可能与当前工作项不同。 |

### 搜索、详情与保存

1. 使用顶栏搜索查找工作项；进入具体页面后，可继续使用页面自身的筛选。
2. 点击工作项打开详情，查看详情、子任务或子项、交付与验收、活动记录。点击编号或链接图标可复制标识和当前工作项链接。
3. 详情中的文本修改通常在结束编辑或失焦后保存；下拉字段选择后提交。等待成功反馈再切换页面，失败时根据提示重试。
4. 项目设置、工作项配置和工作流编辑使用明确的保存按钮。看到“有未保存的修改”时，应先保存或撤销。

侧栏可折叠。分享工作项链接方便定位，但接收者仍须具备对应工作空间的访问资格。

### 在内容中引用工作项

描述、记忆或成果中可以放入工作项链接。可识别的当前项目链接会展示类型、状态、标题和编号，点击打开对应工作项；无法找到目标或无权访问时会显示提示。打开外部链接前会展示目标地址确认，请核对后继续。

## 项目与团队设置

建立项目背景，维护成员职责和共同的完成标准。

### 创建和维护项目

1. 在项目入口选择新建项目，按表单填写名称、项目编号、目标和日期。项目编号用于工作项的显示编号。
2. 进入「项目设置 → 常规」维护名称、描述、目标和周期，点击保存。项目背景与目标会随工作项上下文提供给 AI。
3. 安排工作项日期前，先设置项目周期。缩短项目周期时，先处理超出新范围的工作项。
4. 在「关于」查看当前产品版本、项目名称和保存方式。

> **项目周期与冲刺周期分别管理**
> 工作项计划日期受项目及所属工作项周期限制；安排进某个冲刺并不会自动把工作项日期改成冲刺日期。

### 成员与角色

1. 在「项目设置 → 角色」创建角色，填写名称与职责说明，保存角色。
2. 进入「成员」，输入姓名，选择角色并添加到名册，指定项目负责人后保存成员。
3. 工作项负责人从项目成员中选择。成员名册最多 100 人，角色最多 50 个。
4. 删除角色前，先为使用该角色的成员重新分配并保存；默认成员角色不能删除。

> **名册与访问权限**
> 成员和角色用于记录项目职责。添加姓名或选择“项目经理”不会自动邀请账号或授予项目数据访问权限；当前云项目访问依赖云账号与实际授权。

### 协作约定、完成定义与验收标准

| 记录位置 | 应该写什么 |
| --- | --- |
| 项目设置 → 协作约定 | 共同工作方式，例如遇到阻塞及时说明原因，范围变更前确认。 |
| 项目设置 → 完成定义 | 所有执行项共用的质量标准，例如结果可检查、必要验证通过、负责人确认。 |
| 工作项 → 验收标准 | 当前这项工作的具体完成条件。 |
| 项目设置 → 记忆 | 长期可复用的事实、决定和经验。 |

协作约定与完成定义会提供给 AI，并与工作项自身的验收标准一起使用。请明确写出可验证的要求。

## 创建与维护工作项

填写任务要求、安排负责人和日期，查看交付与变更记录。

### 创建一条工作项

1. 从页面的新建入口或相关区域的右键菜单选择新建工作项。不同页面可带入冲刺、版本或所属工作项。
2. 仅标题必填并以红色星号标记；类型提供默认值，负责人、日期和所属工作项可后补。子任务交付或 AI 执行前需选择标准工作项父级。
3. 按需填写负责人、优先级、计划日期、描述和验收标准，以及目标版本、冲刺和故事点。
4. 保存后打开详情，核对所属关系和实际状态。新项使用类型所绑定流程的初始状态。

普通新建不代表授权 AI 执行。需要 AI 执行时，再在目标工作项详情中明确开启。

### 修改内容和状态

1. 在详情中编辑标题、描述和验收标准，按字段操作保存；通过下拉选择负责人、优先级等属性。
2. 工作项类型在创建时选择，创建后在详情头部只读展示，详情中不再提供类型编辑入口。
3. 点击详情标题左侧的状态图标选择新状态，或在看板拖动至目标状态。系统只允许当前类型工作流中已配置的转换。
4. 若流程要求人工验收，按交付和验收步骤完成工作；普通状态修改不能替代验收。

> **以当前可见入口为准**
> 工作项详情不再单独展示类型和状态编辑字段。状态操作位于标题左侧，需人工验收的工作项仍须通过交付与验收完成。

### 日期、冲刺、版本与故事点

| 字段 | 规则 |
| --- | --- |
| 开始日期、结束日期 | 结束不早于开始；在项目及所属工作项允许周期内。父级排期变化可能同步影响子项。 |
| 冲刺 | 标准工作项可以单独安排；子任务跟随父级冲刺，不可单独移到其他冲刺。 |
| 目标版本 | 与所属冲刺分别安排。调整版本不会自动更换冲刺。 |
| 故事点 | 标准工作项的相对估算；用于容量及部分报告，未估算不代表没有工作量。 |
| 优先级 | 高、中、低，用于排序和排期判断。 |

### 活动、链接和删除

活动记录保留工作项字段变化、执行和验收相关记录。核对变更原因、日期调整和历史版本时，可先查看此处。

删除条目前会提示确认；已有子项、执行记录或冲刺基线的工作项不能直接删除，可按流程取消或调整计划。不要为了清空界面而破坏已经发生的交付记录。

描述等多行内容支持 Markdown 常用标题、粗体、列表和图片粘贴。图片处理完成后再保存；备份不一定包含外部图片和成果链接所指向的文件。

## 工作项类型

按工作性质选择类型，并统一名称、图标和颜色。

### 默认类型与层级

| 类型 | 用途 |
| --- | --- |
| 史诗 Epic | 组织较大的交付目标，包含相关标准工作项。 |
| 故事 | 描述使用者需要达成的结果与验收条件。 |
| 任务 | 明确的研发、设计、调研或运营工作。 |
| 缺陷 | 记录问题、复现条件、预期结果和修复要求。 |
| 子任务 | 把标准工作项拆成更小的行动；创建时可暂不关联父级。 |

同一项目可添加自定义类型。类型代表工作性质；“执行中”应作为状态，而非类型。

### 调整类型配置

1. 打开「项目设置 → 工作项类型」。
2. 修改名称，选择图标和颜色，调整可用性。名称须非空、唯一，最多 40 字。
3. 新增类型时填写名称并添加，再设置显示属性。每个项目最多 40 种类型。
4. 点击「保存工作项配置」，等待成功提示。需要放弃草稿时使用撤销配置修改。
5. 需要不同处理流程时，在「工作流 → 工作流方案」中指定类型映射。未单独指定的类型使用默认工作流。

### 展示、归档与停用

| 可用性 | 效果 |
| --- | --- |
| 展示中 | 新建时可以选择；已有记录保留。 |
| 已归档 | 收起新建入口，保留已有工作项及关联，可恢复展示。 |
| 已停用 | 不能用于新建；仍有工作项使用时不能停用。 |

至少保留一种展示中的标准工作类型。内置类型可改名和调整外观；当前类型管理没有删除入口。改名不改变工作项 ID 和已有内容。

## 工作拆解与日期

维护所属路径，明确父级、子项及计划约束。

### 建立父子关系

1. 打开大项详情，在子项区域添加故事、任务或缺陷；打开标准工作项，在子任务区域继续拆解。
2. 也可以新建时指定所属工作项，或在详情的「所属工作项」中调整关联。
3. 通过详情顶部的所属路径打开上级，通过子项列表查看下级进展。
4. 给每个执行项明确负责人和验收标准。子任务交付后只验收该子任务；父级仍需单独确认。

### 关联规则

所属关系必须在同一项目内，不能关联自己，也不能形成循环。子任务关联父级时只能选择标准工作项，不能继续嵌套子任务。创建时可暂不关联，交付或 AI 执行前需补全父级。可选择的父级会按类型层级过滤。

子任务的冲刺跟随父级；移动父级冲刺时一起调整。在冲刺内可以调整子任务显示顺序，但不能借此把它独立安排到其他冲刺。

### 调整父子日期

工作项计划日期采用双月范围选择器，可留空、单独填写一个端点或清空整个范围；填写后仍须符合项目和父级日期边界。子项周期必须位于父级周期内。在线路中移动或缩放父级条形时，系统可能同步调整子项，并在拖动预览中说明影响数量。保存前检查预览；按 Esc 可取消当前拖动。

父级和项目的时间边界会限制可拖动范围。无法继续拖动时，先检查项目周期、父级周期、日期完整性和是否正在保存。

## 线路与排期

用时间轴检查计划、层级进度和版本里程碑。

### 查看线路

1. 进入「线路」，搜索工作项，按状态、负责人、版本等条件缩小范围。
2. 选择「3 个月」「1 年」「适应」，或在自定义日期中设置时间轴起止范围。
3. 按需选择显示字段、颜色方式和版本里程碑；展开父级查看子项。
4. 点击工作项或条形打开详情。未排期的工作项可从「待排期 · 设置日期」补齐日期。

鼠标经过工作项行时，标题单元格右侧显示加号。点击后在该行下方选择类型、填写标题，失焦或按 Enter 自动保存；空标题或保存失败时保留草稿，按 Esc 可取消。选择同层类型创建同级项，选择更低层类型时按层级规则关联父级。点击工作项标题打开详情；点击日期、状态、负责人、版本或故事点列，可直接编辑该字段。拖动“工作项”列标题的右边缘可调整列宽；聚焦该边缘后可用左右方向键调整，Home/End 设置最窄/最宽，双击恢复默认。列宽在当前浏览器按项目保留。工作项有日期但落在当前时间段外时，会显示范围外提示，可点击定位。改变时间轴范围仅影响查看范围。

### 拖动调整计划

拖动整行工作项到目标行上下四分之一边缘，可放到目标之前或之后；放在中间区域则移入目标。标题、编号、未编辑的字段和行内空白都可作为拖动起点，高亮线表示前后位置，整行高亮表示移入，并显示放置说明；不额外显示拖拽图标。输入控件、展开/新建按钮及时间条保留各自操作。父级移动后，其子项仍跟随展示。也可聚焦工作项行或标题后按 Alt + ↑ / ↓ 调整同级顺序。

任务拖入故事时转为子任务，拖到故事上下边缘则拖出并恢复为任务；编号、负责人、日期、估算和交付历史保留。子任务的冲刺跟随新父级，拖出后继承原父级冲刺；若冲刺已结束，则拒绝提升为独立任务。其他类型的移动遵循项目层级配置。包含子项的任务不能直接转为子任务；不能移入自己或自己的后代。日期超出新父级范围、目标工作流缺少对应状态时，整次移动会被拒绝。移入后自动展开目标，必要时显示子任务层。

松开后同时保存层级和顺序，刷新后保留；仅同级排序不改日期、状态、所属和类型。搜索或筛选启用时暂停拖动，清除筛选后恢复。若其他端已更改顺序、层级、工作项内容或工作流，保存会被拒绝，刷新后重试。

无法放置时显示禁止光标、红色目标行和“无法移动”原因浮层；常见原因包括目标层级不兼容、移入自身后代、计划日期越界或目标工作流缺少对应状态。此时松开不发起保存，也不会改变工作项；松开后保留原因提示。

1. 拖动条形主体，整体平移起止日期；拖动左右边缘，调整开始或结束日期。
2. 观察浮层中的预览日期、边界提示及受影响子项数量。
3. 松开后保存，等待操作完成；按 Esc 可在拖动中取消。
4. 保存后核对父子日期；如期间其他端已修改该工作项，重新读取后再调整。

### 查看进度与里程碑

有子项的条形会展示汇总进度。版本里程碑使用计划或实际发布日期，点击可进入版本详情。逾期提示用于提醒计划风险，不能据此判断实际成果是否已验收。

## 清单、筛选与看板

查找项目工作项，通过列表和状态列推进日常工作。

### 使用清单

1. 进入「清单」，输入标题或工作项编号搜索。
2. 点击列标题的筛选入口，选择状态、负责人、类型等条件；日期字段支持起止范围，点击应用筛选。
3. 通过顶部筛选标签查看当前条件，单独清除某项，或点击「清空」。
4. 点击配置列图标，勾选字段，拖动图标调整列顺序；工作项列固定，也可恢复默认列。
5. 点击排序图标切换升降序；点击行或聚焦后按 Enter 打开详情。

页面显示的数量反映当前筛选结果。找不到工作项时，先清空搜索与筛选、检查列和所属项目。当前清单没有“保存命名筛选”入口。

### 使用看板

1. 进入「看板」，按冲刺、负责人、版本等条件选择范围；需要查看子任务时开启相应选项。
2. 点击卡片查看详情、验收条件和执行记录。
3. 拖动卡片到允许的状态列，按照插入横线放置；同一列内也可调整顺序。
4. 拖动后核对成功提示。目标列不可进入时，检查该卡片类型的工作流转换和人工验收规则。

看板列来自项目启用类型所绑定的流程。同一列存在，不代表所有类型都能进入。当前看板没有配置在制品数量上限的入口。

## 冲刺规划与复盘

明确本轮目标，保存承诺范围，结转未完成工作。

### 创建并安排冲刺

1. 进入「冲刺」，点击「创建冲刺」，填写名称、目标、起止日期和可选故事点容量。
2. 从待办池拖入标准工作项，或通过右键菜单、工作项详情安排冲刺。拖动至插入横线可调整顺序。
3. 需要同时规划版本时，打开「版本」面板，拖入工作项关联版本；所属冲刺保持不变。
4. 检查本轮范围、负责人、验收标准和故事点。子任务跟随父级，默认可隐藏，按需开启显示。

### 启动冲刺

1. 在规划中的冲刺上选择启动，检查名称、目标、日期与范围。
2. 至少安排一个标准工作项；所有纳入的标准工作项均需填写负责人和验收标准。
3. 同一项目同时只能有一个进行中冲刺。已有进行中的冲刺时，先完成它。
4. 确认启动后，系统保存范围基线和故事点快照。执行过程中范围可变化，报告会区分原承诺及后来增减。

启动冲刺不会自动授权 AI，也不会把所有工作项直接完成。计划容量用于规划参考。

### 完成冲刺和结转

1. 在进行中冲刺上选择「完成冲刺」，查看已完成与未完成数量。
2. 填写评审总结、做得好的地方、需要改进的地方；按需填写下次行动。
3. 为每条未完成工作项选择回到待办池、进入已有规划冲刺，或创建后续冲刺。默认去向可统一设置后逐项调整。
4. 按需保留“将改进行动创建为后续工作项”，确认完成冲刺。
5. 进入「历史冲刺」查看完成范围、复盘与结束快照。历史快照不随当前工作项编辑而改变。

> **完成冲刺不会代替工作项验收**
> 未完成项按选择结转，不会因为结束冲刺而被标记完成。已结束冲刺的总结不能继续修改。

## 版本与发布

组织交付范围，保存发布说明和实际交付快照。

### 创建版本与管理范围

1. 进入「发布」，点击「创建版本」，填写版本名称、描述，以及可选的开始日期和计划发布日期。
2. 在列表中双击版本行，或聚焦该行按 Enter，打开详情。
3. 点击「添加工作项」选择范围；也可以在工作项的目标版本中设置，或从冲刺版本面板拖入。
4. 已有未发布版本的工作项转入新版本后，不再属于原版本；其冲刺保持不变。
5. 通过未发布、已发布、全部、已归档分类查找版本。归档会保留关联和发布记录，可恢复。

### 确认发布

1. 完成并验收准备交付的工作项。至少有一项已完成，才能发布版本。
2. 点击「发布版本」，核对交付数量和实际发布日期。
3. 逐项指定未完成工作去向：移出本版本，或延期到其他未发布版本；所属冲刺保持不变。
4. 编辑并检查发布说明，确认发布。系统保存交付快照、实际发布日期和延期去向。
5. 在版本的「发布说明」页签复制或导出 Markdown 说明；已发布版本工作项打开为历史快照。

> **发布记录与上线操作**
> “发布版本”记录已经发生的交付结果。代码构建、应用部署和商店发布需要在相应工具中完成。

## 报告与数据口径

根据问题选择报告，先确认范围和计算依据再解读结果。

### 筛选并阅读报告

1. 进入「报告」，先查看项目快照，再按敏捷与冲刺、流程与效率、计划与交付、工作分布、AI 协作选择报告。
2. 配置可用的冲刺、日期区间、负责人、类型、版本或统计单位。不同报告支持的筛选不同。
3. 报告直接显示结果，筛选调整后自动更新。日期区间不支持未来日期，最多包含 366 个自然日。
4. 点击图表、图例或分组查看对应明细，核对实际工作项。按页面提供的导出入口下载 CSV。
5. 在报告顶部切换报告，或返回目录。可将报告设为常用，并通过最近查看继续上次分析。

### 报告怎么选

| 报告 | 适合回答的问题 |
| --- | --- |
| 冲刺报告、燃尽图、速率图 | 本轮承诺与实际交付差多少？剩余故事点如何变化？历轮交付量怎样？ |
| 累积流程图、控制图 | 工作在哪个阶段堆积？执行周期是否稳定？ |
| 平均年龄报告 | 哪些未完成工作已积压较久？ |
| 新增与完成报告、最近创建报告 | 工作新增与完成是否平衡？新建队列完成情况如何？ |
| 解决时间报告、日期统计报告 | 创建至完成需要多久？按创建、更新、到期或完成日期如何分布？ |
| 饼图报告、单级分组报告 | 按状态、类型、负责人、优先级、版本或冲刺如何分布？ |
| 负责人工作量、剩余工作量分布 | 当前分配给各人的工作及未完成工作占比如何？ |
| 版本工作量报告、版本报告 | 版本交付前还有多少工作？已发布范围是什么？ |
| 目标进展、交付风险 | 目标下的执行工作完成了多少？哪些工作逾期、阻塞或尚未安排交付？ |
| AI 交付与验收 | AI 提交了多少成果？首轮验收结果如何？哪些交付正在等待人工审核？ |

### 理解统计口径与缺失数据

常规统计以标准工作项为主要口径，避免把父级估算与子任务重复累计。故事点和工作项数量是不同单位；未估算工作仍可能占用大量时间。

燃尽图依赖已启动冲刺的每日快照，速率图依赖已结束冲刺。累积流程图和控制图依赖状态变更历史；缺失历史会标记或排除，系统不会凭当前状态补造过去记录。

解决时间是创建至最终完成的自然日时长；执行周期依赖开始与完成记录，可能包含返工。工作量反映分配，不等于工时、个人绩效或产出质量。已发布版本使用发布快照，其他版本使用当前范围。

## 项目记忆

把背景、决定和经验保存下来，让团队与 AI 复用同一份项目知识。

### 记忆有什么用

项目记忆保存跨工作项仍有用的信息。AI 通过获取工作项上下文读取任务时，会一并得到该项目的记忆、目标、协作约定等资料，减少重复说明并保持执行一致。

| 记忆类型 | 适合保存的内容 |
| --- | --- |
| 工作上下文 | 项目背景、业务术语、使用场景、长期边界和已知限制。 |
| 关键决定 | 已确认采用的方案、选择原因、适用范围及后续影响。 |
| 经验与复盘 | 曾经遇到的问题、原因、有效处理方法和后续注意点。 |

### 记录一条记忆

1. 进入「项目设置 → 记忆」，点击「记录记忆」。
2. 选择记忆类型，填写标题和内容；内容必须填写。
3. 建议包含事实或结论、原因、适用范围、日期及参考来源，便于后续判断是否仍有效。
4. 保存后，在记忆列表中核对标题、类型、更新人和更新时间；点击记忆从右侧打开抽屉，可编辑类型、标题和内容并保存。
5. 之后让 AI 执行任务时，要求先获取最新工作项上下文，以便读取项目记忆。

> **当前是人工记录**
> 记忆需要人工记录，不会从聊天自动提取。点击列表中的记忆可在右侧抽屉编辑；“修改历史”保留各次保存的内容、操作人和时间。删除需确认，删除后移入“已删除”列表，历史仍可查看，AI 不再收到该记忆。

### 写什么，放在哪里

| 内容 | 建议位置 |
| --- | --- |
| “所有页面统一称为工作项，避免混用条目和任务” | 记忆：长期术语约定。 |
| “本次新增筛选按钮，需支持清空和无结果提示” | 当前工作项的描述与验收标准。 |
| “所有交付需提供检查入口及验证结果” | 项目协作约定或完成定义。 |
| “上轮冲刺遇到图片上传未完成导致保存失败，提交前需等处理完成” | 经验与复盘。 |

记忆属于项目上下文，不会让 AI 自动获得其他账号、文件或项目的访问权限。信息失效时，可编辑原记忆并保存，旧版本保留在修改历史中；不再适用的记忆可以删除。

## AI 协作与人工验收

连接 AI、明确授权、跟踪执行，并由人检查最终成果。

### 配置 AI 与 MCP 连接

1. 打开「项目设置 → AI 与 MCP」，检查服务状态，选择「查看连接配置」。服务正常只说明 HeySO 服务可用。
2. 在支持 MCP 的 AI 客户端配置页面提供的地址与授权方式。LoyoCloud 使用云服务的 /mcp/heyso 并通过 OAuth 登录、选择允许访问的项目；独立工作空间使用本站 /mcp 及界面提供的令牌。
3. 返回 AI 客户端刷新工具列表，确认能够列出项目并获取目标工作项上下文。
4. 连接地址、授权范围或令牌失效时，回到连接配置重新核对。保管令牌，不要写入公开文件。

具体工具由当前连接提供。LoyoCloud 的工作项创建和编辑还需 heyso:write 授权；旧连接可能需要重新授权。

### 开启目标工作项的 AI 执行

1. 先在类型所绑定的工作流中配置执行、验收与完成协作节点，以及必要转换路径。
2. 打开故事、任务、缺陷、子任务或自定义执行类型的详情，点击机器人按钮启用 AI 执行。
3. 核对目标工作项的描述、验收标准、负责人、日期和所属关系。
4. 复制或提供目标工作项的执行指令，交给已经连接 MCP 的 AI，并要求先读取最新上下文。

子任务可以随父级执行授权生效，也可明确停用该子任务的 AI 执行。以目标详情中的实际开关为准；开启开关只授予执行回传资格，不代表已经启动 AI。

### AI 执行如何回传

| 阶段 | HeySO 中发生什么 |
| --- | --- |
| 读取上下文 | 获取项目、所属层级、目标工作项、子项、记忆、冲刺版本及历史审核。 |
| 报告进展 | 更新目标工作项和执行记录为执行中或阻塞，说明进展或阻塞原因。 |
| 提交成果 | 提交交付说明、验证结果和成果链接，进入待人工验收。 |
| 人工验收 | 负责人检查后选择通过或要求修改。AI 不能自行验收完成。 |

要求变更后需重新读取上下文。执行记录会显示所依据的工作项版本；旧版交付不能自动视为满足新要求。继续同一次执行时复用返回的执行记录标识，提交重试复用同一次交付的请求标识，避免重复记录。

### 检查交付与要求修改

1. 在「智能」或工作项详情的「交付与验收」中打开交付，检查执行者、说明、验证结果、成果链接和进展。
2. 打开成果链接实际检查。链接只记录位置，不会自动上传文件；接收人必须能访问对应成果。
3. 若出现要求版本变化提示，先对照当前验收标准检查差异，需要时勾选已核对声明。
4. 选择通过，确认目标工作项完成；或要求修改，写明未满足条件及修改要求。
5. 重新提交后再验收。子任务通过不会自动完成父级；父级仍按自己的验收标准确认。

AI 交付的标准工作项经人工验收通过后，其直属子任务会统一进入各自工作流的完成状态（包括待开始、执行中、阻塞、待验收和已取消的子任务），并记录完成时间与触发来源。已完成子任务保持原记录。提交成果或要求修改时不会触发同步；单独验收子任务也不会改变父级或其他子任务。子任务独立的 AI 执行记录与审核意见保持原样。若子任务工作流缺少完成节点，整次验收会被拒绝，需先补齐配置。

需要人工记录外部执行结果时，可在允许的目标工作项上使用「记录交付」，填写执行者、交付说明、验证方式和链接。是否显示该入口取决于当前状态及 AI 授权。

### 供连接配置时参考的工具

| 工具 | 用途 |
| --- | --- |
| list_projects / query_project | 列出项目，查询工作项、配置、版本与冲刺。 |
| get_story_context | 获取执行上下文；名称中的 story 也用于兼容其他执行类型。 |
| create_item / update_item | 若当前连接提供且已授权，可创建或编辑工作项；不会自动启用 AI，也不能代替状态或验收工具。 |
| update_progress | 报告执行中或阻塞。 |
| submit_result | 提交成果进入待人工验收。 |

不同服务与连接版本可能提供不同工具；以客户端实际刷新得到的清单为准。

## 工作流与状态配置

按类型配置处理路径，并按需接入人工验收和 AI。

### 状态库、工作流、工作流方案

| 配置 | 作用 |
| --- | --- |
| 状态库 | 统一维护状态名称、待办／进行中／完成三类属性及可用性。 |
| 工作流 | 选择状态、初始状态和允许的单向转换。 |
| 工作流方案 | 为每种工作类型指定流程，并选择默认流程。 |
| HeySO 协作规则 | 绑定执行、阻塞、验收、完成等节点，配置是否要求人工验收。 |

状态名称不会自动产生审批行为。把状态叫“待验收”，仍需在协作规则中绑定验收节点并设置转换路径。

### 维护状态库

1. 打开「项目设置 → 工作流 → 状态库」。
2. 填写新状态名称，选择待办、进行中或完成类别，再添加状态。名称非空、唯一，最多 40 字；项目最多 40 个状态。
3. 修改名称会影响所有引用它的流程；已有工作项使用的状态类别不能直接更改，可新增状态后迁移。
4. 停用状态前先移除所有工作流引用。仅新增到状态库，不代表已加入某个工作流。
5. 点击当前页面的「保存更改」。

### 新建、复制与编辑流程

1. 在「工作流」列表点击「新建工作流」；也可使用复制按钮，或双击已有行进入全屏编辑。项目最多 20 个流程。
2. 设置唯一名称，添加新状态或复用状态库中的已有状态。选择属于当前流程的初始状态。
3. 通过「添加转换」填写名称、起点、终点。选中转换可编辑，或使用添加反向转换。每个流程最多 160 条转换。
4. 拖动节点调整图示位置。节点位置不会自动创建状态转换。
5. 点击「保存并返回」。离开有改动的编辑器时，可以继续编辑、放弃或保存后返回。

| 转换形式 | 含义 |
| --- | --- |
| A → B | 只允许 A 到 B，不自动允许 B 到 A。 |
| 任意状态 → B | 允许流程中的任意状态进入 B。 |
| A → A | 保留同状态转换关系，不执行额外自动化动作。 |

移除状态会影响与其相关的转换和节点绑定。先更换初始状态，才能移除原初始状态。系统校验引用合法性，但仍需人工检查开始、完成、返工及取消路径是否可达。

### 绑定类型与迁移现有工作项

1. 切换到「工作流方案」，选择默认工作流，并为需要独立处理的类型指定流程。
2. 若新流程不包含已有工作项的当前状态，为每组受影响工作项选择迁移目标。
3. 检查 AI 工作项的协作节点是否兼容；需要时补齐节点或先关闭受影响工作项的 AI 执行。
4. 点击「保存更改」，等待成功后回到详情和看板核对。
5. 已有状态仍合法时保留当前状态；只有需要迁移的组按指定目标改变。保存不会统一重置所有工作项。

> **配置影响整个项目**
> 类型和工作流可能共用配置草稿。保存前检查全部改动，尤其不要把未完成项错误迁移到完成类别。重要变更前先备份。

### 配置人工验收和 AI 协作

1. 可复制「交付验收工作流」作为起点，在全屏编辑器进入「HeySO 协作规则」。
2. 按需要绑定待开始、执行、阻塞、验收、完成和取消节点。不同节点不能绑定同一状态。
3. 待开始使用待办类；执行、阻塞、验收使用进行中类；完成、取消使用完成类。
4. 启用 AI 至少绑定执行、验收、完成节点，并配置执行 → 验收、验收 → 完成及验收 → 执行等实际路径。
5. 需要时开启「完成前须人工验收」，点击完成返回，再保存工作流。普通人工流程可以不使用这些扩展节点。

当前支持状态、初始状态、单向、任意起点及同状态转换、类型映射与协作节点。没有转换权限条件、校验器、后置操作和自动化触发器配置。

### 练习：为缺陷建立独立流程

1. 新建“待分诊”（待办）、“修复中”（进行中）、“已修复”（完成）三个状态。
2. 新建“缺陷处理”流程，加入这三个状态，初始状态设为待分诊。
3. 添加“开始修复”：待分诊 → 修复中；“提交修复”：修复中 → 已修复；“重新打开”：已修复 → 修复中。
4. 保存流程，在工作流方案中为缺陷绑定该流程，再保存更改。
5. 创建一条练习缺陷，检查初始状态，依次推进并重新打开。完成练习后按项目规则处理练习数据。

## 云端连接与数据备份

分清页面、数据和连接设置，正确导出与恢复项目。

### 数据保存在哪里

| 方式 | 保存位置与特点 |
| --- | --- |
| 本机运行 | 由本机 HeySO 服务保存至其数据目录，浏览器负责操作界面。 |
| LoyoCloud | 每个项目以 .heyso 文件保存在所连接的云账号中，使用云文件历史版本。 |
| Upstash / Cloudflare | 整个工作空间保存在所配置的存储服务中，依赖对应地址、凭据及存储标识。 |

Netlify 等负责页面和服务托管，不代表项目数据也存在那里。换浏览器、清除连接 Cookie 或连接过期后，可能需要重新连接；这本身不会删除云端项目。

### 首次配置和重新连接

1. 新部署首次打开时，由部署者在向导中使用初始化密钥验证身份。
2. 选择 LoyoCloud、Upstash 或 Cloudflare，完成授权或填写连接信息，检查连接。
3. 检查通过后设置工作空间访问密码，完成配置。
4. 重新连接或切换存储时，从顶栏云端存储入口进入向导。确认连接的是原账号、原地址及原存储标识。

> **切换连接不等于迁移**
> 切换后看到另一份项目列表，并不表示原数据丢失。连接向导不会自动复制旧存储的数据。迁移前先导出、核对，再导入目标存储。

### 导出与导入

1. 进入「项目设置 → 数据与备份」导出工作空间 JSON；在「AI 与 MCP」的 LoyoCloud 云空间区域导出或导入单个项目 .heyso 文件。
2. 工作空间 JSON 包含所有项目及相关记录，适合整体备份；.heyso 用于逐项目保存和迁移。
3. 保存备份至你可管理的位置，重要配置调整、迁移和恢复前另存一份当前备份。
4. 导入 .heyso 时检查目标账号及冲突提示；名称、编号或标识冲突可能阻止导入。

备份不包含 MCP 访问密钥，也不会自动打包成果链接指向的外部文件。需要长期保存的成果应另行备份。

### 恢复工作空间或云文件

1. 独立工作空间恢复：选择 HeySO 导出的 JSON 备份，等待检查，核对当前与备份记录数量和恢复后的项目。
2. 先保存或撤销其他设置草稿；确认备份正确后，输入“恢复”并确认。恢复会替换整个工作空间的全部记录，不是只合并当前项目。
3. LoyoCloud 模式不支持用 JSON 一次替换整个云账号；需使用云文件历史版本恢复单个项目，或通过 .heyso 导入。
4. 恢复后重新打开项目，检查工作项、记忆、配置和交付记录；外部成果文件仍需独立检查。

恢复与导入有文件大小及服务容量限制，以当前界面和服务返回的提示为准。LoyoCloud 项目删除应在云空间移至回收站，不要误用整体恢复来删除单个项目。

## 常见问题与排查

根据现象检查连接、数据、配置与任务要求。

### 登录、同步和数据问题

| 现象 | 排查步骤 |
| --- | --- |
| 打开页面要求重新配置 | 确认是否换浏览器、清理了 Cookie 或连接已过期；重新连接原账号和存储。 |
| 项目突然不见了 | 先核对连接的账号、服务地址与存储标识，避免在空工作空间新建同名项目造成混淆。 |
| 保存失败或版本冲突 | 保留待提交内容，确认网络及账号授权有效，读取最新数据后按提示重试。不要用旧内容覆盖他人新修改。 |
| 其他设备修改暂未显示 | 返回前台或刷新后检查；刷新前先保存或复制尚未提交的草稿。 |
| 恢复按钮不可用 | 检查备份是否通过预检、确认文字是否正确，以及其他设置是否还有未保存草稿。 |
| 成果链接打不开 | 核对地址、文件是否存在、接收人是否有访问权限；HeySO 记录链接不等于上传文件。 |

### 工作项和规划问题

| 现象 | 排查步骤 |
| --- | --- |
| 找不到某条工作项 | 清除搜索、状态、负责人、版本和冲刺筛选；打开子任务显示，检查所属项目。 |
| 无法设置或拖动日期 | 检查项目周期、父级周期、起止日期及当前是否正在保存。 |
| 无法启动冲刺 | 至少安排一个标准工作项，补齐负责人和验收标准，并先结束同项目的进行中冲刺。 |
| 子任务无法独立移动冲刺 | 子任务跟随父级；从父级修改冲刺。 |
| 版本无法发布 | 至少完成一项工作，并为剩余未完成项指定去向，填写发布说明和实际发布日期。 |
| 历史内容与详情不同 | 你正在查看启动、结束或发布时的快照；当前工作项可能后来发生变化。 |
| 报告为空或历史未知 | 核对筛选、日期、故事点及历史记录；新项目可能尚无启动快照、已结束冲刺或完整状态变更。 |

### 类型和工作流问题

| 现象 | 排查步骤 |
| --- | --- |
| 新增类型在新建入口不可见 | 先保存，确认类型处于展示中且启用。 |
| 无法停用类型或状态 | 检查已有工作项及工作流引用；保留至少一种展示中的标准类型。 |
| 某个状态不能选择或拖入 | 检查工作项类型绑定流程、当前到目标状态的转换方向及人工验收要求。 |
| 工作流保存失败 | 检查重复名称、初始状态、转换引用、迁移目标和协作节点类别，补齐 AI 所需节点。 |
| 工作流无法删除 | 先解除类型绑定，并更换默认流程。 |
| 刷新后配置草稿丢失 | 配置需要点击保存，草稿不是自动发布的。已发布配置目前没有直接回滚按钮。 |

### AI 与记忆问题

| 现象 | 排查步骤 |
| --- | --- |
| 启用 AI 按钮不可用 | 在该类型流程中绑定执行、验收、完成节点，并保存配置。 |
| AI 提示没有权限 | 确认客户端已连接正确工作空间、项目授权有效、目标 AI 执行开启。云端创建和编辑需相应写入授权。 |
| AI 提示要求版本已变化 | 重新获取上下文，核对工作项及父级要求，再继续执行或提交。 |
| 提交后仍未完成 | 成果进入待人工验收，需负责人检查后确认通过。 |
| AI 没有采用新共识 | 确认记忆已经手动保存，并让 AI 重新获取最新工作项上下文。 |
| 连接工具列表与说明不同 | 重新授权并刷新工具列表；以当前连接实际提供的工具为准。 |

### 建议的日常使用节奏

1. 开始工作前：确认本轮目标、待办优先级和验收标准。
2. 执行中：及时更新状态，阻塞时说明原因，减少同时进行的工作。
3. 交付时：提供实际可访问的成果和验证结果，由负责人检查。
4. 每轮结束：完成冲刺、结转未完成工作，记录改进行动。
5. 关键决定后：将长期结论记入项目记忆，定期导出备份。
