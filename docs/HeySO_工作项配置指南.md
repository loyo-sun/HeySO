# HeySO 帮助中心

工作项类型、层级关系与工作流配置指南。依据当前版本的实际操作编写。

## 工作项类型

定义“这是什么工作”，统一名称、图标和颜色。

### 先分清类型、层级和状态

一条工作项可以是“任务”类型，属于“标准工作项”层级，目前处于“执行中”状态。类型说明工作性质；层级规定父子关系；状态说明处理进度。三个概念分别配置，不要用类型名称代替进度。

| 配置对象 | 回答的问题 | 例子 |
| --- | --- | --- |
| 工作项类型 | 这是什么工作？ | 故事、任务、缺陷、调研 |
| 层级关系 | 哪些工作可以成为它的父级？ | Epic → 标准工作项 → 子任务 |
| 工作流 | 从哪里开始，可以流转到哪里？ | 待开始 → 执行中 → 已完成 |

> **建议的学习顺序**
> 先确定类型，再把类型放入层级，最后为类型绑定工作流。类型管理中的“可用性”控制创建入口，不是工作项的进度状态。

### 默认类型怎么用

| 类型 | 默认层级 | 适用场景 |
| --- | --- | --- |
| 史诗（Epic） | Epic · 1 | 一组相关需求或较大的交付目标 |
| 故事 | 标准工作项 · 0 | 从使用者角度描述一项可验收的需求 |
| 任务 | 标准工作项 · 0 | 明确的研发、设计、运营等执行工作 |
| 缺陷 | 标准工作项 · 0 | 记录与预期不符、需要修复的问题 |
| 子任务 | 子任务 · -1 | 把一个标准工作项拆成更小的行动 |
| 战略主题、特性 | Epic · 1，默认归档 | 可选规划类型，需要时恢复展示并按需调整层级 |

故事、任务、缺陷默认同层并列。任务不是故事的子项类型；需要拆分故事时，创建“子任务”。类型名称可以修改，判断父子关系依据实际层级，不依据名称。

### 编辑名称、图标、颜色和可用性

1. 打开「项目设置 → 工作项类型」。
2. 在列表中直接修改名称。名称不能为空、不能重复，最多 40 字。
3. 点击图标，选择一个图形；点击颜色，选择预设色或自定义颜色。选择后点击空白处，或按 Esc 关闭浮层。
4. 按需调整“可用性”，通过上下箭头调整类型顺序。
5. 点击「保存工作项配置」。出现保存成功提示后生效。点击「撤销配置修改」可放弃当前类型、层级、工作流的共同草稿。

| 可用性 | 创建新工作项 | 已有数据 |
| --- | --- | --- |
| 展示中 | 可以选择该类型 | 正常保留 |
| 已归档 | 不在新建入口展示 | 工作项和关联保留；可恢复展示 |
| 已停用 | 不能创建 | 已有工作项使用的类型不能停用 |

> **至少保留一个标准工作类型**
> 项目必须保留至少一种展示中的标准工作类型。类型图标与颜色会用于层级卡片、列表、创建入口和详情；切换工作流不会重置它们。

### 新增一种工作类型

1. 在类型列表底部填写「新类型名称」，例如“调研”。
2. 选择它所属的层级。独立执行的调研通常选择「标准工作项」。
3. 点击「添加类型」，再在新行里设置图标、颜色等属性。
4. 点击「保存工作项配置」。每个项目最多 40 种类型。
5. 如需独立处理流程，再去「工作流 → 类型映射」为它指定工作流；未单独指定时使用默认工作流。

新增类型时先想清楚它是否代表长期稳定的工作性质。“进行中”“已完成”应作为状态；“本周”“重要”通常也不适合作为工作类型。

### 创建工作项和转换类型

1. 在项目管理中点击「新建工作项」，选择工作类型。
2. 填写标题、负责人和日期等信息，按需要选择父级；子任务必须选择标准工作项作为父级。
3. 保存后，工作项自动使用该类型绑定工作流的初始状态。
4. 修改已有工作项时，在详情中选择同层级的其他类型。若原状态不属于目标流程，界面会要求选择转换后的状态，再点击「确认转换」。

> **转换前检查关联和 AI 配置**
> 转换仍须满足父级、子项和日期约束。启用 AI 的工作项还需要目标流程具有执行、验收和完成节点；需要时先关闭该工作项的 AI 执行。当前详情仅提供同层级类型转换。

### 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 新类型为什么没有出现在创建入口？ | 确认已保存，且类型为“展示中”。归档、停用或尚未保存的类型不会作为新选项出现。 |
| 名称旁的“内置类型”能删除吗？ | 内置类型保留标识，可改名、改图标、改颜色，或在允许的情况下归档、停用。当前类型管理不提供删除入口。 |
| 为什么“已停用”选项不可选？ | 该类型仍有工作项，或它是最后一种展示中的标准类型。可用归档隐藏创建入口并保留数据。 |
| 改名会改变原有工作项吗？ | 显示名称随配置更新，工作项 ID、内容和父级关系保留。 |

## 层级关系

先配置类型所在层级，再整理具体工作项的父子关系。

### 两个“层级”入口有什么区别

| 入口 | 操作对象 | 作用 |
| --- | --- | --- |
| 项目设置 → 层级关系 | 工作类型 | 把故事、任务等类型放入层级分组，制定父子约束 |
| 项目管理 → 工作项层级 | 实际工作项 | 把某条工作项关联到另一个具体父级，或拖拽归类 |

> **拖动类型不会自动搬动工作项**
> 设置页拖动的是类型卡片。它改变类型分组规则，不会自动替现有工作项更换父级。已有父子关系不符合新规则时，会列出冲突并阻止保存。

### 默认三级与父子约束

| 层级 | 默认类型 | 可以关联的父级 |
| --- | --- | --- |
| Epic · 1 | 史诗 | 可选更高规划层的工作项；也可不关联 |
| 标准工作项 · 0 | 故事、任务、缺陷 | 任意更高层级的工作项；也可不关联 |
| 子任务 · -1 | 子任务 | 必须关联标准层工作项，不能直接放到 Epic 下 |

同层工作项不能互为父子。父子必须属于同一个项目，不能关联自己或形成循环。日期还需在项目和父级的周期内。标准工作项可以直接关联更高规划层，并不要求每个规划层都有中间工作项。

例如：史诗“优化登录体验”下放故事“用户通过验证码登录”、任务“接入短信服务”、缺陷“验证码提示错误”。故事下再拆子任务“实现验证码输入框”。任务、缺陷和故事彼此是同层类型。

### 用拖拽配置类型分组

1. 进入「项目设置 → 层级关系」。
2. 按住类型卡片，将它拖入目标层级；也可使用卡片上的「所属层级」下拉框完成同样操作。
3. 不需要展示的类型，拖入右侧「归档」区，或点击卡片的归档按钮。归档区随页面浮动。
4. 恢复类型时，把归档卡片拖回目标层级；点击恢复按钮则按它原有层级恢复展示。
5. 检查页面提示和已有数据冲突，点击「保存工作项配置」。保存前都只是草稿。

> **有数据时的限制**
> 已有工作项的类型不能跨“规划、标准、子任务”类别移动；规划层之间的移动仍须满足现有父子关系。内置子任务类型固定在子任务层。不能把最后一种展示中的标准类型归档。

### 增加、命名和移除层级

1. 点击「添加层级」，填写名称并点击「添加」。新扩展层会放在当前最高层之上。
2. 直接编辑层级标题可重命名，例如把新增层级命名为“战略目标”。
3. 把相应工作类型放入新层级；如需新类型，先在「工作项类型」中添加。
4. 移除自定义层级前，先移出该层的全部类型，包括归档、停用的类型，再点击层级标题旁的删除按钮。
5. 保存配置。项目最多 12 层；Epic、标准工作项、子任务三个基础层必须保留。

层级右侧的工作项数量可帮助判断影响范围。层级名称可以改，标准层位置仍固定为 0，子任务层固定为 -1。

### 恢复默认与智能推荐

| 功能 | 如何处理类型 | 如何处理数据 |
| --- | --- | --- |
| 恢复默认 | 未使用的内置类型恢复默认分组；战略主题、特性默认归档；使用中的类型和必要扩展层保留 | 不删除工作项，不重置图标、颜色或工作流 |
| 智能推荐 | 有数据的类型保留展示与所属层；无数据的类型归档，并整理未使用类型的分组 | 不删除或自动移动工作项；若标准层没有使用中的类型，保留一种标准类型供新建使用 |

这两个按钮都先生成草稿。检查展示和归档结果后再保存；不满意可撤销配置修改。它们不会强行把使用中的历史层级压缩成三级。

### 整理具体工作项的父级

1. 返回项目管理，进入「工作项层级」。
2. 拖动某条工作项到合法的父级工作项上，或在工作项详情中修改父级。
3. 移动时，子项跟随现有子树关联；系统会检查项目、层级、循环和日期约束。
4. 子任务只能归属于标准工作项。想让故事包含独立“任务”类型的工作项时，应先重新考虑拆分方式；默认结构应使用子任务。

> **配置和数据保存方式不同**
> 项目设置中的调整需要点击保存；实际工作项的创建、父级变更和状态变更，操作成功后即保存到本地。不要把设置草稿误认为实际工作项已经移动。

### 已有数据冲突怎么处理

1. 先读冲突清单，确认受影响工作项及其现有父级。此时配置尚未保存，原数据仍在。
2. 可以撤销本次分组调整，保留原规则；也可以先撤销草稿，回到工作项详情整理类型或父级，再回来配置。
3. 同层类型转换可在详情中完成；跨规划、标准、子任务的已有类型调整目前不能直接批量迁移。遇到这种需求时，应保留使用中的类型，新建目标类型后规划迁移。
4. 保存层级变更会记录上一版方案；需要整体恢复数据时使用「数据与备份」。配置历史目前没有可直接点击回滚的界面。

“恢复默认”是生成一份默认分组建议，不是撤销上一次保存。尚未保存用“撤销配置修改”；重要变更前建议先下载工作空间备份。

## 工作流

自定义状态与流转路径，按类型配置处理方式。

### 状态库、工作流和类型映射

| 配置 | 负责什么 | 例子 |
| --- | --- | --- |
| 状态库 | 统一维护可复用的状态名称和类别 | “待分诊”“修复中”“已修复” |
| 工作流 | 选择状态、初始状态和允许的单向转换 | 待分诊 → 修复中 → 已修复 |
| 类型映射（工作流方案） | 为每种工作类型指定流程 | 缺陷用“缺陷处理”，任务用“标准工作流” |

所有状态归入三种进度类别：待办、进行中、完成。类别用于颜色和进度统计；你可以在每种类别下自定义多个状态。“待评审”和“测试中”都可以属于进行中。状态名字不自动产生审批、取消等行为。

> **不是固定模板**
> 标准工作流、交付验收工作流只是起点，可以编辑或复制；也可以从单个初始状态新建流程。人工验收是 HeySO 的可选扩展，不是所有工作流必须经过的步骤。

### 第一步：准备状态库

1. 打开「项目设置 → 工作流」，切换到「状态库」。
2. 在底部填写新状态名称，选择待办、进行中或完成类别，点击「添加状态」。例如新增待办类“待分诊”、进行中类“修复中”、完成类“已修复”。
3. 已有状态可直接改名。名称须唯一、非空，最多 40 字；项目最多 40 个状态。
4. 改名会同步影响所有引用该状态的流程。已有工作项使用中的状态不能直接修改类别；请新增目标状态后迁移。
5. 要停用状态，先从所有工作流中移除引用，再关闭“启用”。当前不提供删除已有状态的入口。

> **新增状态还没有加入流程**
> 状态库是可复用资源。新增后，还要在具体工作流里“添加状态”，再配置转换。仅有名称相似，并不代表两个状态是同一个状态。

### 第二步：新建或复制工作流

1. 切换到「工作流」页签，点击左侧标题旁的加号，新建流程；或选择一个已有流程，点击右侧复制图标。
2. 修改工作流名称，例如“缺陷处理”。名称不可重复，每个项目最多 20 个流程。
3. 在「选择已有状态」中依次选择所需状态，点击「添加状态」。
4. 设置「初始状态」。新建工作项会直接进入它；保存工作流不会把所有已有工作项重置到初始状态。
5. 点击节点或状态标签可编辑名称；拖动图中的节点调整位置，排布也随配置保存。移除状态会一并移除其关联转换和协作节点绑定；初始状态须先更换才能移除。

初始状态必须属于当前工作流。当前编辑器通过下方的转换列表建立关系；拖动图中的节点只调整图示位置，不会自动连线。

### 第三步：设置允许的转换

1. 在「状态转换」下填写转换名称，如“开始修复”。
2. 选择起点“待分诊”、终点“修复中”，点击「添加转换」。
3. 再添加“提交修复”：修复中 → 已修复。若允许退回，单独增加“重新打开”：已修复 → 修复中。
4. 直接编辑已有转换的名称、起点或终点；点击该行的叉号可移除转换。
5. 若所有状态都能进入某个状态，起点选「任意状态」。也可以配置起点与终点相同的转换。每个流程最多 160 条转换。

| 设置 | 实际效果 |
| --- | --- |
| A → B | 只允许从 A 到 B，不自动允许 B 到 A |
| 任意状态 → B | 该流程中的任意状态均可进入 B |
| A → A | 允许同状态转换；当前仅保留此关系，不执行额外自动化动作 |
| 只加入状态 B，没有连到它的转换 | 已有工作项不能仅因 B 在流程中就直接切换到 B |

> **自由配置，也要检查路径**
> 系统校验转换引用是否合法，但不会替你保证每个状态都能到达完成。发布前，请按真实操作顺序检查开始、提交、返工、重新打开等路径。

### 第四步：绑定工作类型并发布

1. 切换到「类型映射」，设置方案名称和默认工作流。未单独指定流程的类型使用默认工作流。
2. 为缺陷选择“缺陷处理”；其他类型可继续选择「使用默认工作流」。同一流程可供多种类型使用。
3. 如果目标流程不包含某些现有工作项的当前状态，页面会出现「发布前迁移状态」。为每组工作项选择目标状态。
4. 检查新状态归属和已有 AI 工作项的协作节点兼容性，点击「发布工作流配置」。
5. 看到成功提示后，回到工作项详情验证可选状态。创建时使用初始状态；已有工作项保留当前状态，只有明确指定迁移的组会变更状态。

> **发布影响整个项目**
> 类型、层级与工作流共用一份配置草稿；在任一栏目保存都会一起提交。迁移可选择目标流程中的有效状态，不限定同类别，因此要特别检查是否会把未完成事项迁为完成。发布失败时整体回滚，不会只迁移一部分。

### 动手练习：为缺陷建立独立流程

1. 在状态库建立“待分诊 / 待办”“修复中 / 进行中”“已修复 / 完成”。
2. 新建“缺陷处理”，加入这三个状态，初始状态选择“待分诊”；移除不需要的默认初始状态前，先换好初始状态。
3. 添加：开始修复（待分诊 → 修复中）、提交修复（修复中 → 已修复）、重新打开（已修复 → 修复中）。
4. 在「类型映射」把缺陷绑定到这个流程。其余类型保持默认，发布配置。
5. 新建一条缺陷，确认初始状态是“待分诊”。在详情切换为“修复中”，再切为“已修复”；直接从待分诊到已修复应不可选。
6. 回到工作看板，核对新状态列。看板按启用的标准类型所绑定流程汇总列；某列存在不代表每个类型都允许进入该状态。

练习会生成实际工作项和配置。需要保留当前环境时，先在“数据与备份”下载备份，或新建练习项目再操作。

### 可选：人工验收与 AI 协作

1. 需要验收流程时，可先复制「交付验收工作流」。展开下方「HeySO 协作规则」。
2. 分别绑定待开始、执行、阻塞、验收、完成、取消节点；未使用的节点可以不绑定。不同协作节点必须使用不同状态。
3. 执行、阻塞、验收节点使用进行中类状态；待开始使用待办类；完成、取消使用完成类。
4. 如要启用 AI，至少分别绑定执行、验收、完成节点，并配置实际需要的转换，如开始执行、执行 → 验收、验收 → 完成、验收 → 执行。绑定节点不替代转换配置。
5. 按需开启「完成前须人工验收」。开启后，标准工作项不能通过普通状态选择直接标记完成，需要提交交付后人工验收。子任务不受这项标准工作项完成限制。
6. 发布并绑定到对应工作类型，再在工作项详情开启 AI 执行。普通人工工作流无需配置这些扩展节点。

> **状态名称不等于协作节点**
> 仅把状态取名为“待验收”，不会自动接入人工验收。必须绑定验收节点，并设置合法的流转路径。若把已启用 AI 的类型换到缺少节点的流程，须补齐节点或先关闭受影响工作项的 AI 执行。

### 排查保存、流转和历史问题

| 现象 | 检查顺序 |
| --- | --- |
| 发布按钮不可点击 | 确认确有改动；补全状态迁移；解决层级冲突或已有 AI 工作项的节点冲突。 |
| 点击发布后提示配置无效 | 检查重复名称、初始状态是否仍在流程内、转换起终点是否有效、协作节点类别是否匹配且没有复用状态。 |
| 某个状态在详情中不可选 | 检查类型绑定的流程、当前状态到目标状态的转换方向，以及是否开启人工验收。 |
| 看板拖到目标列失败 | 列可能属于另一种类型的流程；当前类型仍按自己的转换规则校验。 |
| 不能删除工作流 | 先把使用它的类型切换到其他流程；若是默认流程，先换默认流程，再删除。 |
| 状态类别改不了或保存失败 | 已有工作项正在使用该状态，或协作节点绑定的类别与新类别不符。新增状态并明确迁移通常更稳妥。 |
| 修改后刷新丢失 | 草稿只保留在当前页面，需点击发布；刷新提醒不是自动保存。 |
| 想回到旧配置 | 未发布可撤销共同草稿；已发布会留存上一版配置记录，目前没有直接回滚按钮。重要变更前先下载备份，恢复备份会替换整个工作空间。 |

当前支持状态、初始状态、单向/全局/同状态转换和类型映射。尚未提供转换权限条件、校验器、自动化触发器、后置操作或点击图形端口连线。不要把流程图节点排布当作这些能力。
