# HeySO 合序 · alpha_0.1

**合而有序，让人与 AI 围绕共同成果协作。**

Hey, Shared Outcomes.

HeySO 是一款面向个人与小型项目的敏捷项目管理工具。把想法拆成清晰的工作项，安排优先级与冲刺，让执行进展、AI 交付和人工验收在同一个项目中衔接起来。

从「要做什么」到「成果是否符合预期」，每一步都有据可查。

## 用 HeySO，把工作组织起来

### 从目标拆到行动

用史诗、故事、任务、缺陷和子任务组织项目。树状层级呈现工作的归属，拖动即可调整父级；搜索子项时保留父级路径，随时看清上下文。

搜索与层级操作栏支持滚动吸顶。拖到不允许放入的位置时，红色提示与红 X 会说明当前操作不可用。

### 在时间轴上规划交付

Roadmap 将工作项和版本里程碑放在同一条时间轴上，支持年、季、月、天四档颗粒度。拖动时间条调整周期，拉伸两端修改起止日期，点击即可编辑；浮动气泡实时显示日期和受影响的子项数量。

子项周期保持在父级范围内。移动父级时子项跟随，收缩父级时越界子项同步收拢。横向滚动条固定在页面底部，日期表头与筛选栏随页面滚动保持悬浮。

### 为下一步确定顺序

在产品待办池中集中查看标准工作项，按优先级整理工作，搜索标题或编号，按状态与负责人筛选，再安排到版本和 Sprint。

工作项层级与产品待办池使用同一批数据：前者帮助你理清结构，后者帮助你安排交付顺序。

### 让每个冲刺连接实际交付

规划冲刺目标与容量，启动时保留范围基线，在看板中推进工作。执行中查看进度、燃尽与范围变化，结束时记录评审和复盘，为未完成工作安排下一步。

版本管理将工作项与发布目标关联，记录发布说明，并保留实际发布范围。

### 让 AI 接得住工作，让人验得了成果

为工作项写清目标和验收标准，按需授权 AI 执行。接入支持 MCP 的外部 AI 工具后，AI 可以读取项目上下文、报告进展与阻塞、提交成果说明和链接。

在启用交付验收规则的工作流中，负责人查看成果，确认通过或提出修改意见。交付记录与审核历史留在项目中，后续接手时可以继续追溯。

### 用自己的方式管理流程

按项目需要配置工作项类型、图标、颜色和层级。使用可视化工作流编辑器设置状态与转换，为不同类型绑定不同流程。

成员名册记录负责人和角色职责；工作约定、完成定义和项目记忆帮助你明确协作要求。

## 一个项目，多种视角

| 页面 | 你可以做什么 |
| --- | --- |
| 项目概览 | 查看项目目标、当前冲刺、版本计划和待验收成果 |
| Roadmap 路线图 | 查看完整计划周期，拖动调整工作项日期，跟踪版本里程碑 |
| 工作项层级 | 拆分目标、调整父级、查看完整工作结构 |
| 产品待办池 | 整理优先级，筛选工作项，安排版本与冲刺 |
| 工作看板 | 按状态推进工作，查看不同 Sprint 的执行情况 |
| Sprint 冲刺 | 规划、启动、评审、复盘与结转工作 |
| 版本发布 | 组织版本范围，记录发布说明与交付快照 |
| 项目记忆 | 保存背景、关键决定与可复用经验 |
| AI 交付 | 跟踪 AI 执行、查看成果并处理验收 |

工作项支持右键快捷操作，可直接修改状态、负责人、优先级、故事点和交付安排。活动记录逐字段保留修改前后的值，便于追溯日期、状态、负责人、父级、描述等变化；历史记录中未保存的旧值不会补造。

### 首次使用，跟着配置向导完成连接

1. 点击部署按钮，在平台中设置自己的 `HEYSO_SETUP_KEY`：至少 32 位随机初始化密钥。
2. 打开部署完成的网址，在向导中输入初始化密钥，确认部署者身份。
3. 选择 **LoyoCloud / Upstash / Cloudflare**，登录账号或填写连接信息，检查连接。
4. 设置工作空间访问密码，进入工作空间。已有项目会继续保留。

选择 LoyoCloud 时，项目直接保存在云空间，不需要额外数据库。选择 Upstash 时，填写数据库的 REST 地址和读写密钥。选择 Cloudflare 时，可使用本实例的 Durable Objects，或连接单独部署的 Cloudflare 存储服务。

连接设置加密保存在当前浏览器的 HttpOnly Cookie 中，数据库凭据不会写入网页存储或项目备份。换设备、清除 Cookie 或连接过期后，可以重新连接同一份云端数据。进入后可通过顶栏的「云端存储」重新打开向导；切换后端不会自动迁移项目。

详细步骤、独立 Cloudflare 存储服务、数据迁移和故障排查见 [部署指南](docs/DEPLOYMENT.md)。托管与存储服务可能根据账号套餐和使用量计费。

## 开始使用

需要安装 **Node.js 20.19 或更高版本**。

```sh
git clone https://github.com/loyo-sun/HeySO.git
cd HeySO
npm install
npm run build
npm start
```

在浏览器打开 [http://localhost:4179](http://localhost:4179)。

macOS 用户完成安装与构建后，也可以双击项目中的「启动 HeySO.command」。

### 试着完成你的第一个工作项

1. 打开内置示例项目，或创建自己的项目，填写目标与起止日期。
2. 在「工作项层级」中创建史诗，再拆成故事、任务或缺陷；需要时继续拆分子任务。
3. 在详情中明确负责人、验收标准、优先级和计划日期。
4. 从待办池挑选近期要做的工作，安排进 Sprint；启动冲刺后，在看板中推进状态。
5. 如果希望交给 AI 执行，先按下方说明连接 AI 工具，再为相应工作项启用 AI。
6. 检查成果，按所选工作流完成工作或进行人工验收，在冲刺结束时记录复盘。

点击页面右上角的问号，可以打开内置帮助中心。完整操作说明见 [HeySO 用户帮助手册](docs/HeySO_用户帮助手册.md)，覆盖快速开始、项目设置、工作项、线路、冲刺、看板、版本发布、报告、记忆、AI 协作、工作流及数据备份。

## 连接你的 AI 工具

HeySO 通过 MCP 向外部 AI 工具提供项目上下文、工作项创建和编辑，以及执行入口。

工作项管理使用 `create_item` 和 `update_item`：先调用 `query_project` 读取配置及 `revision`，写入时传入 `expectedRevision`、唯一 `requestId` 和 `agent`。创建需填写类型、标题和起止日期；编辑在 `patch` 中传入要修改的字段。相同请求重试复用 `requestId`；版本冲突时重新读取并使用新请求标识。

LoyoCloud 需单独授权 `heyso:write`（创建和编辑工作项）；已有连接需重新授权并刷新工具列表。创建、编辑无需启用 AI，不能更改 AI 权限、状态或代替人工验收。

1. 进入「项目设置 → AI 与 MCP」，查看连接地址与密钥。
2. 在支持 HTTP MCP 和自定义请求头的 AI 客户端中完成连接配置。
3. 为需要协作的工作项启用 AI，复制执行指令，交给已连接的 AI 工具。
4. 在「AI 交付」中查看执行进展、成果与审核记录。

默认本机连接地址为 `http://127.0.0.1:4179/mcp`，使用 `Authorization: Bearer <密钥>` 验证。请只将密钥交给你信任的工具。

外部 AI 工具需单独配置；本地服务就绪并不代表 AI 已接入。实际文件修改、命令执行和代码操作由外部工具完成。纯云端客户端通常不能直接访问本机地址。

## 本地保存，也可连接 LoyoCloud

**本地使用**：项目默认保存在本机，支持工作空间 JSON 备份与恢复。数据目录为 `.data/`，请保留该目录，并定期导出备份。恢复备份会替换整个本地工作空间。

**在线项目**：连接 LoyoCloud 个人账号后，可将单个项目转为在线 `.heyso` 文件，打开云端项目，并导入或导出 `.heyso` 文件。在线项目支持自动保存与版本冲突检查，也为远程 AI 协作提供云端 MCP 入口。

在线功能需要可用的 LoyoCloud 服务与账号；本仓库提供 HeySO 应用，云端服务独立部署。

## 关于 alpha_0.1

这是 HeySO 的早期可用版本，已支持本地与在线部署、工作流配置、Sprint 与版本管理，以及通过 MCP 进行的人与 AI 协作。

本地应用采用单用户模式；在线部署采用访问密码保护的单工作空间模式。成员与角色用于责任记录，不提供按成员划分的项目权限。在线项目支持 LoyoCloud 个人账号，团队多人权限尚未提供。当前版本也不提供附件托管、AI 一键启动、部署执行或 Git 托管；成果可通过链接或本地路径记录。

示例项目与示例 Agent 记录用于体验流程，不代表相应功能已由某个外部 AI 工具实际交付。

欢迎通过 [GitHub Issues](https://github.com/loyo-sun/HeySO/issues) 反馈使用问题和改进建议。

## 本地开发

```sh
npm run dev
npm test
```

开发服务默认使用 `4179` 端口，可通过 `PORT` 修改；可通过 `HEYSO_DATA_DIR` 指定独立数据目录。测试 AI 协作时，建议使用专门的测试项目。
